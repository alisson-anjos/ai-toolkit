# Source-targeted H3 reward pilot

The existing Character Swap LoRA supplies replacement appearance. Frozen Molmo identifies the original character by a reference crop and emits observations with normalized coordinates and timestamps. The caption carries the original-character description and trajectory, linked explicitly to replacement Picture 1. This first prototype uses the existing projector on that textual/visual context; it does not add a newly trained trajectory projection branch.

The dataset uses original guide clips in `targets/` solely for latent shape and guide context. There is no edited target supervision. `control_0` contains the unmarked guide, `control_1` the replacement image, and `source_people` the original-character crop, with matching stems. Human and animal sources are supported by the preparation workflow. In `judge_context/<stem>.json`, provide guide/source_photo/replacement_photo paths, instruction, target_binding description/points, fps and sampled times. Only confirmed source observations enter the dataset; unresolved bindings must be excluded.

`config/examples/molmo_h3_targeted_rl_5090.yaml` uses DiffusionNFT with two sequential rollouts, frozen four-step DMAD for rollouts only, resolution384/39frames, pruned ConvRot H3, and frozen Character Swap/Ostris-v2 during updates. The new delta starts from the source-photo pilot. Run the frozen Molmo preparation before H3 training and unload its GPU process first.

The `bfs_targeted_reward_worker.py` worker calls the OpenAI Responses API, keeping the key outside the dataset/config. Set `OPENAI_JUDGE_MODEL`, `BFS_JUDGE_REPORT_DIR`, and either `OPENAI_API_KEY` or `BFS_JUDGE_KEY_FILE`. `BFS_JUDGE_MAX_CALLS` bounds requests (default 200); group size two uses two calls per training example. Preserve reports to audit the selected target and reward. Failed API calls stop reward assignment and low-confidence/uncertain responses get no reward. The shaped training reward keeps strict full credit for a correct swap, gives a smaller target-grounding signal when the right person is selected but unchanged, penalizes a wrong-person swap, and gives partial credit to mixed swaps. Inspect `nft_log.jsonl` and individual grades: an optimizer-step counter alone does not establish a useful update.

Calibrate before optimization. On a small boxing control, a photo-only GPT prompt initially chose the wrong original target; adding the verified Molmo identification/trajectory distinguished the known wrong-target result, correct-target result and unchanged guide. This is a limited calibration, not a generally validated reward. Frame-based assessment can miss temporal errors, preservation scores are imperfect, and rewards can be exploited. Multi-target scoring is not implemented in this initial worker.

The 5090 example is configured for 500 steps and checkpoints every 25 steps. The run still needs live verification of rewards, memory, throughput and learned selection. Check `nft_log.jsonl` and sampled videos rather than treating decreasing loss or step counts as proof of correct targeting.
